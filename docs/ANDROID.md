# Android (and iOS) app

The Android app is a Capacitor 8 shell around the native web build (`apps/web/dist-native`) plus one native plugin, `InkwrightNative`, for the things a WebView cannot do: low-latency writing sound and haptic grain read straight from the stylus, the instant ink tip, stylus button keys, on-device handwriting recognition and high refresh rate. The primary device is the Motorola Razr Fold with the Moto Pen Ultra; everything also works on any Android 8.0+ phone or tablet.

apps/web/android/                    the Gradle project (generated by `cap add android`, then customised)
  app/build.gradle                   app id, versions, ML Kit, Kotlin, release signing
  app/src/main/AndroidManifest.xml   permissions, foldable config changes, launch theme
  app/src/main/java/app/inkwright/

## Build

Requirements: Node 20+, JDK 21, Android SDK with platform 36 and build-tools 36 (`ANDROID_HOME` set, or `sdk.dir` in `apps/web/android/local.properties`). Android Studio's bundled JDK and SDK work.

```sh
# from the repo root
npm install
npm run build:native -w @inkwright/web     # vite build --mode native → apps/web/dist-native
cd apps/web && npx cap sync android       # copy dist-native + plugin list into the Android project
cd android && ./gradlew assembleDebug     # → app/build/outputs/apk/debug/app-debug.apk
```

`npm run android -w @inkwright/web` does all three steps. Other useful tasks, run in `apps/web/android`:

| Task | What it does |
|---|---|
| `./gradlew testDebugUnitTest` | JVM unit tests for the plugin's pure logic |
| `./gradlew lintDebug` | Android lint (report in `app/build/reports/`) |
| `./gradlew assembleRelease` | release APK (signed with your key if `keystore.properties` exists, else the debug key) |
| `./gradlew bundleRelease` | release App Bundle for Google Play → `app/build/outputs/bundle/release/app-release.aab` |
| `./gradlew signingReport` | SHA-1/SHA-256 of the debug and release keys (needed for Google sign-in) |

Run `npx cap sync android` again after every web build; Gradle only packages what is already in `android/app/src/main/assets/public`. You can also open `apps/web/android` in Android Studio and press Run.

If Gradle fails with `429 Too Many Requests` from `repo.maven.apache.org`, wait a minute and rerun; it resumes where it stopped. For repeated failures, use Google's mirror of Maven Central for that build only, without changing the project:

```groovy
// ~/mirror.init.gradle — use with: ./gradlew assembleDebug --init-script ~/mirror.init.gradle
def MIRROR = 'https://maven-central.storage-download.googleapis.com/maven2/'
beforeSettings { it.pluginManagement.repositories { maven { url MIRROR } } }
allprojects {
    buildscript { repositories { maven { url MIRROR } } }
    repositories { maven { url MIRROR } }
}
```

## Install on the Razr Fold

1. On the phone: Settings → About phone → tap **Build number** seven times. Then Settings → System → Developer options → turn on **USB debugging** (or **Wireless debugging**).
2. Connect by USB and accept the prompt, or pair over Wi-Fi with `adb pair <ip>:<port>` then `adb connect <ip>:<port>`.
3. Install:
   ```sh
   adb install -r dist/Inkwright-debug.apk        # or apps/web/android/app/build/outputs/apk/debug/app-debug.apk
   ```
   Without adb: copy the APK to the phone, open it in Files, and allow "Install unknown apps" for Files when asked.
4. Debug the web layer from a computer: open `chrome://inspect` in Chrome on the computer while the phone is connected (debug builds only). Native logs: `adb logcat -s InkwrightNative InkwrightRecognizer Inkwright`.

The debug APK is signed with this machine's debug key. Installing a build signed with a different key over it fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`; uninstall first (`adb uninstall app.inkwright`, which deletes the app's local notes, so sync or export them first).

First run notes:

- **Handwriting recognition** downloads the ML Kit model for your language (about 20 MB) the first time recognition is needed, in the background. Until it is there, `prepareRecognizer` answers `downloading` and the app uses another engine (or none). After that it works offline. A download that fails is retried on the next request, up to three times per app launch.
- **Haptic grain** uses touch-feedback vibration. If Settings → Sound & vibration → Vibration & haptics → **Touch feedback** is off, Android silences it, by design.
- **Audio notes**: the first recording asks for the microphone permission.

## What the native layer does

**`capabilities()`** → `{ richHaptics, recognition: true, stylusKeys: true }`. `richHaptics` is true when the actuator supports the `LOW_TICK` or `TICK` composition primitive (the Razr Fold does).

**`grain({ intensity })` / `confirm()`** resolve immediately. The vibration is played on a dedicated `HandlerThread` at display priority with touch-feedback attributes. The effect is `PRIMITIVE_LOW_TICK` (or `TICK`, or a 4 ms amplitude-scaled pulse on older motors) scaled by intensity. Effects are prebuilt per intensity step. A tick that waited more than 40 ms in the queue, or comes less than 5 ms after the previous one, is dropped: by then it no longer matches the pen. `confirm()` is a `PRIMITIVE_CLICK`.

**`prepareRecognizer({ language })`** → `ready` (model on the device), `downloading` (download started or still running), `failed` (three failed downloads this session) or `unsupported` (no ML Kit model for the tag or its base language, e.g. `de-AT` falls back to `de`).

**`recognize({ language, lines })`** → `{ lines }` with one string per input line. It runs off the main thread. Each line is recognized with `WritingArea(width, height)` and a pre-context: the line's `preContext` if the web layer sent one, otherwise the previous recognized line plus a space (the last 20 characters). It rejects with code `NOT_READY` if the model is not on the device yet.

**`stylusButton` event** `{ pressed, keyCode }`: `MainActivity.dispatchKeyEvent` forwards `KEYCODE_STYLUS_BUTTON_PRIMARY/SECONDARY/TERTIARY/TAIL` (308–311; AOSP has no other stylus key codes). It sends one `pressed: true` per press and ignores auto-repeat and duplicate downs. It sends one `pressed: false` per release, plus a synthetic release if the window loses focus mid-press. These keys are consumed, so the WebView does not also see them. The editor uses them as the external button (`Editor.tsx` → `engine.setExternalButton`).

**Opening files from other apps** ("Open with Inkwright", "Share to Inkwright"): `AndroidManifest.xml`
has `VIEW` and `SEND`/`SEND_MULTIPLE` intent filters for PDFs, images, plain text and Markdown. The
plugin (`InkwrightNativePlugin` → `files/IncomingFiles.kt`) reads the intent that started the
activity (`load`) or arrived later (`handleOnNewIntent`; the activity is `singleTask`), copies the
content off the main thread into `cacheDir/incoming/` (the `content://` grant only lasts as long as
the intent) and hands `{ name, mimeType, path }` to the web layer: the `sharedFiles` event when it is
listening, otherwise `takeSharedFiles()` returns them. Shared text without a file becomes a `.txt`.
The web layer (`lib/openFiles.ts`) reads each copy with Capacitor Filesystem, imports it like the
library's Open file and deletes the copy.

**`insertCalendarEvent({ title, beginTime, endTime, allDay, description?, location? })`** → `{ opened }`:
"circle a date" opens the user's calendar app on a prefilled new event (`Intent.ACTION_INSERT` on
`CalendarContract.Events.CONTENT_URI`, built in `calendar/CalendarIntents.kt`). The user confirms it
there; Inkwright never reads or writes the calendar itself, so no calendar permission is needed.
`opened` is false when no calendar app handles the intent (the web layer then offers the .ics file).

**Refresh rate**: the activity asks for the display mode with the highest refresh rate at the current resolution, and asks again after fold/unfold, which can move it to another panel. This costs some battery while Inkwright is in the foreground. That is the trade for ink that keeps up with the pen.

**Unbuffered input**: on Android 11+ the WebView calls `requestUnbufferedDispatch(SOURCE_CLASS_POINTER)`, so pen samples are handed to Chromium as they arrive instead of once per frame. Set `UNBUFFERED_POINTER_DISPATCH = false` in `MainActivity.kt` to go back to the default.

**Foldables**: the activity is resizeable and declares every configuration change a fold, unfold, rotation, display move or dark-mode switch causes (`…|screenSize|smallestScreenSize|screenLayout|density|uiMode|colorMode`). The WebView is never recreated and an open note keeps its state. The window and WebView background follow light/dark mode (`#DDE2E6` / `#14181C`, the web app's theme colours), and the Android 12+ splash uses the same colours with the slate icon.

**Permissions**: `INTERNET`, `VIBRATE`, `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS`. Capacitor's `BridgeWebChromeClient` asks for both when the page calls `getUserMedia({ audio })` and grants only if both are granted, so the second is required. There is no `CAMERA` permission on purpose: `<input capture>` opens the system camera app, which needs no permission while the app does not declare `CAMERA`. Libraries add a few more (WorkManager from ML Kit, Credential Manager from Google sign-in).

**Google sign-in** (Drive sync) uses `@capgo/capacitor-social-login`. Requesting Drive scopes needs the activity to forward authorization results, so `MainActivity` implements `ModifiedMainActivityForSocialLoginPlugin` and passes those results to `onActivityResult`. Only the Google provider is bundled (`capacitor.config.ts` → `SocialLogin.providers`). In Google Cloud Console, create an **Android** OAuth client for package `app.inkwright` for each signing key's SHA-1: debug, upload key, and Play App Signing key. The web client ID is the one the app passes as `webClientId`.

## On-device AI (no API key, nothing leaves the phone)

The app runs its assistant, summaries and voice input on the phone's own NPU/GPU through three
native engines, all in `app/inkwright/ai/` and reached through `InkwrightNativePlugin`'s `ai*` and
`speech*` methods (the wire format is documented on `AiBridge`). The web side is
`apps/web/src/ai/native/` (bridge) and `apps/web/src/lib/native-ai.ts` (status, downloads,
choice), which registers the engines as `NativeLLM`s; `pickAssistant` prefers a ready native
engine over the in-WebView model (docs/LOCAL_AI.md). Settings › AI › On this device shows each
engine with its status and download button.

| Engine | What it is | Which phones | Download |
|---|---|---|---|
| **Gemini Nano** (ML Kit GenAI Prompt API) | Google's model inside Android's AICore, shared by all apps, run on the NPU | AICore phones only (table below). AICore answers `unavailable` everywhere else, including the emulator | Done by Android once (AICore reports the size when it starts and the app shows progress), started from Settings or the assistant's offer |
| **Writing tools** (ML Kit GenAI summarization, proofreading, rewriting, image description) | Gemini Nano with task-tuned adapters | Same phones as Gemini Nano. Summaries: English, Japanese, Korean; proofreading/rewriting: also German, French, Italian, Spanish; image descriptions: English | Small adapters, by Android |
| **Open model** (LiteRT-LM 0.19) | Gemma 4 E2B / E4B or Qwen3 1.7B / 0.6B, `.litertlm`, on the GPU (OpenCL) with CPU fallback | Any arm64 phone with enough memory (the model list disables models above the phone's memory) | From Hugging Face, pinned to a commit, SHA-256-checked, resumable |
| **Voice input** (`SpeechRecognizer`) | Android's on-device recognizer (Android 12+ where installed), else the default recognizer with "prefer offline" | Most phones; on-device where Google's offline speech is installed | Language packs by Android |

How each behaves:

- **Status** comes from `checkStatus()` / `checkFeatureStatus()` and maps to `available`,
  `downloadable`, `downloading`, `unavailable` (`EngineState`). AICore errors become stable codes
  with plain messages (`GenAiErrors`): `busy` (another app is using it, or the per-app quota),
  `quota` (daily battery quota), `background` (AICore only runs for the app on screen), `update`
  (AICore too old), `unsupported`, `too-large`.
- **Generation** streams: each chunk goes to the web layer as an `aiDelta` event, batched to one
  event per ~60 ms or 24 characters (`StreamAssembler`, which also copes with engines that resend
  the whole text). `aiCancel` cancels the coroutine; ML Kit's flow and LiteRT-LM's
  `cancelProcess()` stop decoding. Requests run on `Dispatchers.Default`/`IO`; only
  `SpeechRecognizer` calls hop to the main thread, as Android requires.
- **Prompts**: the web layer sends system + turns (already budgeted). `ChatPromptBuilder` merges
  same-role turns, drops a leading assistant turn, refuses a conversation that doesn't end with the
  person, and trims to the engine's context. Gemini Nano gets a system instruction when AICore
  supports one (else it is folded into the first turn) and multi-turn contents, falling back to a
  single flattened message if an AICore version rejects that shape. LiteRT-LM gets a fresh
  conversation per request with `enable_thinking: false` (Qwen3 otherwise thinks first).
- **Open-model downloads** go to `noBackupFilesDir/models/litert/<file>.part` (2 GB must not count
  against Android's backup quota), resume with an HTTP `Range` request after a drop or an app
  restart, check free space first (keeping 512 MB spare), verify the SHA-256 and only then rename
  the file and write a `.ok` marker. The web layer asks before downloading, showing the size and
  licence. Models are pinned to a Hugging Face commit because litert-community re-exports files
  under the same name for newer runtimes (`LiteRtModels.kt`).
- **Memory**: one LiteRT engine is loaded at a time and stays loaded between questions; switching
  or deleting the model unloads it. The default model follows `ActivityManager` total memory:
  Gemma 4 E2B from ~7 GB (an "8 GB" phone), Qwen3 1.7B from 5 GB, Qwen3 0.6B from 3 GB. Gemma 4 E4B
  is offered on 12 GB+ phones but never the default.
- **NPU for open models** is not used: LiteRT-LM's NPU backend needs a model compiled for one
  specific chip plus the vendor's dispatch libraries bundled in the APK. Gemini Nano already uses
  the NPU on AICore phones.
- **GPU** needs the vendor's OpenCL library, which apps targeting Android 12+ may only load when
  declared: the manifest has `<uses-native-library android:name="libOpenCL.so" android:required="false"/>`
  (and `libvndksupport.so`). Without it the engine falls back to the CPU (slower, more memory).
- **Voice**: live push-to-talk (`speechStart`/`speechStop`) uses segmented sessions on Android 13+
  so pauses don't end it, with partial results as `speechPartial` events. Recordings are
  transcribed with `speechTranscribe` (16 kHz mono PCM through `EXTRA_AUDIO_SOURCE`, Android 13+,
  on-device recognizer only) — that is the web layer's `Transcriber`. The first live session asks
  for the microphone permission if the WebView hasn't already.

## The Moto Pen Ultra's buttons

The pen reaches the app in two separate ways.

- **Tip, eraser and barrel button (USI 2.0, through the screen's digitizer).** These are ordinary stylus input. Android reports the barrel button as `MotionEvent.BUTTON_STYLUS_PRIMARY`, and the WebView turns it into pointer events: `pointerType === 'pen'` with `buttons & 2` while it is held. The eraser end gives `buttons & 32`. No native code is involved, and this is what the editor relies on first.
- **The Bluetooth button.** Motorola routes this to its own system features (for example a pen shortcut that opens a Moto app or takes a screenshot). Whether an app ever sees the press depends on Motorola's software, not on Inkwright:
  - While the Moto shortcut is assigned, the system consumes the press and Inkwright cannot receive or override it. An app cannot take precedence over a system-level key handler.
  - If you set the pen-button shortcut to **None** (or turn it off) in Moto's pen settings (Settings → Moto Pen / Stylus on Moto builds), some builds then deliver the press to the foreground app as a key event. If it arrives as one of the stylus key codes (308–311), Inkwright forwards it as `stylusButton` and the editor treats it like the barrel button. If it still does nothing, Motorola keeps it for itself on that build.
  - On Android 14+ stock settings (Settings → Connected devices → Stylus), make sure **Ignore all stylus button presses** is off, if your build shows it.
  - To see what the button sends: `adb shell getevent -lt` (raw input) or `adb logcat | grep -i keycode` while pressing it. If it sends a different key code (for example a `KEYCODE_MACRO_*`), add that number to the key set given to `StylusKeyFilter` in `MainActivity.kt`.

We have not verified on a Razr Fold which of these the current Moto software does. Check with `getevent` before relying on the Bluetooth button.

## Text input and `captureInput`

`capacitor.config.ts` sets `android.captureInput: false`, so text fields keep the WebView's full editor connection: predictive text, autocorrect, glide typing, non-Latin IMEs and Android's **"Write in text fields"** stylus handwriting all work. Setting it to `true` makes Capacitor substitute a plain `BaseInputConnection` (raw key events, but none of the above); only do that if you need raw keys, then run `npx cap sync android`.

## Backups

The app opts out of Android's cloud backup (`android:allowBackup="false"`,
`res/xml/data_extraction_rules.xml`, `res/xml/backup_rules.xml`). Everything Inkwright keeps is in
the WebView's storage, and the key that encrypts API keys and MCP sign-ins sits in the same
IndexedDB files as the ciphertexts: "non-extractable" stops scripts from reading it, not a copy of
the files. A Google Drive backup of the app would therefore carry the API keys in effect in the
clear (security review SR-03). Notes reach other devices through the app's own sync; on Android 12+,
setting up a new phone from the old one (device-to-device transfer) still moves everything.
`src/platform/android-manifest.test.ts` fails if a change brings cloud backup back or exports a
component.

## Release on Google Play

1. **Create an upload key** once, and keep it and its passwords somewhere safe (a password manager plus an offline backup). Losing it means asking Google to reset the upload key.
   ```sh
   keytool -genkeypair -v -keystore ~/keys/inkwright-upload.jks -alias inkwright \
     -keyalg RSA -keysize 2048 -validity 10000
   ```
2. **Point the build at it** with `apps/web/android/keystore.properties`. It is git-ignored along with `*.jks` and `*.keystore`; never commit it.
   ```properties
   storeFile=/Users/you/keys/inkwright-upload.jks   # absolute, or relative to apps/web/android
   storePassword=…
   keyAlias=inkwright
   keyPassword=…
   ```
   Without this file (or with a field missing), release builds are signed with the debug key and Gradle prints a warning. Play rejects such builds.
3. **Build the bundle**: bump `versionCode` (and `versionName`) in `app/build.gradle`, then
   ```sh
   npm run build -w @inkwright/web && (cd apps/web && npx cap sync android)
   cd apps/web/android && ./gradlew bundleRelease
   # → app/build/outputs/bundle/release/app-release.aab
   ```
   Release builds leave out the web source maps. Code shrinking (R8) is off, the Capacitor default, because plugins are found by reflection.
4. **Play Console** (play.google.com/console, one-time $25 developer account): create the app, accept **Play App Signing** (Google holds the app signing key; your key is only the upload key), and upload the `.aab` to **Internal testing** first. Then fill in Data safety (microphone for audio notes; network for sync and AI, both user-initiated), content rating, target audience and the privacy policy URL, and promote to production.
5. **Google sign-in in Play builds**: copy the SHA-1 from Play Console → App integrity → App signing → **App signing key certificate**, and add an Android OAuth client for `app.inkwright` with it. Play-installed apps are signed with that key, not with your upload key.

## iOS (on a Mac)

The Xcode project is already generated in `apps/web/ios` (Swift Package Manager, no CocoaPods). On the Mac:

```sh
npm install                                  # repo root; restores node_modules the Swift packages point into
npm run build -w @inkwright/web
cd apps/web && npx cap sync ios              # copies dist into ios/App/App/public and refreshes Package.swift
npx cap open ios                             # opens ios/App/App.xcodeproj in Xcode
```

If `apps/web/ios` is ever missing, recreate it with `npx cap add ios --packagemanager SPM` from `apps/web`, then re-add the usage strings below.

In Xcode, select the **App** target → Signing & Capabilities, choose your Team, and keep the bundle identifier `app.inkwright` (or change it if that ID is taken). Then pick your iPad or iPhone and Run. For the App Store: Product → Archive → Distribute App. `Info.plist` already has the microphone, camera and photo-library usage strings.

- **Apple Pencil** works through Pointer Events (`pointerType === 'pen'`, pressure, tilt, coalesced events, hover on iPads that support it). It needs no native code. Pencil double-tap/squeeze (`UIPencilInteraction`) is not delivered to web content; it would need a small native plugin.
- **`InkwrightNative` is Android-only** (`hasNativePlugin` is false on iOS). Haptic grain is off, and handwriting recognition uses the browser or AI engines.
- **Google sign-in on iOS** needs an iOS OAuth client: `SocialLogin.initialize` must also get `iOSClientId` (and `iOSServerClientId` = the web client ID), and the reversed client ID must be added as a URL scheme (Info → URL Types). `apps/web/src/lib/google.ts` passes them when `VITE_GOOGLE_IOS_CLIENT_ID` is set.
